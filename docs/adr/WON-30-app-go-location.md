# WON-30: app.go 위치를 internal/app/으로 변경

## 문제

Wails v2 기본 스캐폴딩은 바인딩 구조체(`app.go`)를 프로젝트 루트에 둔다. 하지만 프로젝트 원칙상 모든 비즈니스 로직은 `internal/`에 있어야 하며, 바인딩 메서드가 늘어나면 루트가 지저분해진다.

## 검토한 대안

| 대안 | 설명 | 장점 | 단점 |
|------|------|------|------|
| 루트 `app.go` | Wails 기본 관행 | 공식 문서/예제와 일치 | 루트에 비즈니스 코드 위치, 파일 분리 어려움 |
| `internal/app/app.go` | 프로젝트 구조 원칙 준수 | 깔끔한 루트, 파일 분리 용이, internal/ 원칙 부합 | Wails 관행과 다름 |

## 결정

`internal/app/app.go`에 둔다.

## 이유

- **프로젝트 적합성 우선 원칙(0번)**: 일반 관행보다 프로젝트 구조에 맞는 것을 선택
- Wails는 바인딩 구조체가 루트에 있어야 한다는 기술적 제약이 없음. `main.go`에서 import하면 동일 작동
- 바인딩 메서드가 늘어났을 때 `internal/app/` 안에서 파일 분리가 자유로움
