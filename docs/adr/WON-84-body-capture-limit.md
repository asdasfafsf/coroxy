# WON-84/93: Body 캡처 크기 제한

## 문제

HTTP 프록시에서 request/response body를 캡처할 때, 대용량 파일(동영상, 바이너리 등)을 전부 메모리에 저장하면 OOM 위험.

## 검토한 대안

| 대안 | 설명 | 장점 | 단점 |
|------|------|------|------|
| A. 제한 없음 | 모든 body를 전부 캡처 | 데이터 손실 없음 | OOM 위험, 메모리 폭발 |
| B. 2MB 제한 | API 응답만 커버 | 안전 | 웹페이지, 이미지 잘림 |
| C. 32MB 제한 | 대부분의 웹 트래픽 커버 | 실용적 | 대용량 파일은 잘림 |
| D. 디스크 스트리밍 | body를 파일로 저장 | 제한 없음 | 구현 복잡, I/O 오버헤드 |

## 결정

C. 32MB 제한 (maxCaptureSize). HTTP/HTTPS 통일.

## 이유

- 32MB면 대부분의 API 응답, 웹페이지, 이미지를 커버
- 프록시 자체의 동작(클라이언트 전달)에는 영향 없음 — 캡처만 제한
- 메모리 스토어 기반에서 현실적인 타협점
- 디스크 스트리밍은 SQLite 영속 저장 구현 시 함께 검토
